# The Pirate Archipelalgo

A print-first, screen-free computer-science adventure for children. The reader
acts like a tiny computer: following references, tracking state, calling
functions, testing conditions, searching ordered data, and combining parallel
results with pencil and paper.

The book is organised as eight dream nights with Morrow, the Eight-Handed
Cartographer, while the Blank Tide erases routes between algorithmic islands.

## Project shape

The project is intentionally split into four layers:

1. `data/` and `content/` contain authored book material.
2. `domain/` contains the hunt program, solver, source loader, and address compiler.
3. `utils/bookStructure.ts` validates the compiled book and builds its graph.
4. `components/` renders editor, child-print, and adult-answer editions.

Child-facing prose is not parsed to determine correctness. Each hunt owns an
explicit `HuntProgram`; simulations, validation, reachability, and answer pages
all derive their path from that program.

## Commands for a later validation pass

No generated files are committed by the source-only migration. When ready:

```sh
npm install
npm run typecheck
npm test
npm run build
npm run preview
```

The browser editor has separate **Child PDF** and **Adult PDF** print actions.
For deterministic Playwright PDFs, keep the preview server running and use:

```sh
npm run pdf:child
npm run pdf:adult
```

Set `BOOK_URL` if the preview is not at `http://127.0.0.1:4173`, and `PDF_PATH`
to choose another output filename. Set `PAPER_FORMAT=Letter` for a US Letter
edition; A4 is the default. PDF generation stops if a page overflows its fixed
paper box.

## Human-authored hunts

`content/example-hunt.yaml` documents the YAML format. The loader in
`domain/huntSource.ts` validates it with Zod and converts it into the same
executable model used by code-authored hunts.

Every program step has:

- a stable `sourceId` used by authors and tooling;
- a printed `refId`, retained during the current migration;
- child-independent editor text;
- its expected page;
- an explicit transition generated by `createLinearProgram`.

Future content should use semantic tokens such as:

```text
{{ref sandy-shores.skull-rock}}
```

`domain/addressCompiler.ts` resolves these tokens after page and slot allocation.
This lets pages move without rewriting clue prose. Printed addresses use
`page.slot`, with a two-digit slot such as `10.02`. Map positions use a separate,
zero-based `column.row` convention.

## Adding a hunt

1. Create the references and any map markers.
2. Add a YAML hunt with a unique ID and stable step IDs.
3. Assign the hunt to a night in `data/nights.ts`.
4. Run validation when dependencies are available.
5. Inspect both child and adult print editions.

The validator checks duplicate addresses, two-digit slots, page/address
agreement, grid markers without log entries, missing program nodes, broken
transitions, non-terminating programs, expected-page mismatches, unreachable
pages, and night references to missing hunts.

## Print principles

- Production print does not require CDN styles or web fonts.
- The child edition receives no answer-path highlighting.
- Treasure and decoy semantic types are not exposed as icons.
- Coordinates and reference text are sized for paper use.
- Print CSS forces a monochrome representation and supports A4 or Letter geometry.
- Adult answer paths are derived from executable programs.

Before publishing, check actual laser-printer output for clipping, contrast,
duplex alignment, and readability in a moving car.

## Curriculum

The eight-night progression is:

1. references and pointer chains;
2. state, loops, and iteration;
3. reusable functions;
4. conditionals and predicates;
5. sets, filtering, and aggregation;
6. ordered data and binary search;
7. indirection, transformations, and the call stack;
8. parallel work, merging, and debugging.

Each night contains a dusk story, Morrow’s challenge, one or more hunts, a dawn
reflection, and a sigil for the final mystery.

### Centrepiece paper hunt

Night Seven now includes **The Dream Below the Dream**. The child follows Morrow
through three nested dreams, writing each promised return address into a printed
stack. At the deepest level the outward trail disappears. Escaping requires
crossing out and following the saved addresses in last-in, first-out order.

This is deliberately not explained to the child as a “call stack” before play.
The physical need comes first; the adult/editor answer guide supplies the
computer-science name afterward.
